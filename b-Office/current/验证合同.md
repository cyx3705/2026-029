# HistoryJuno 验证合同

## 验证原则

- 每项现行需求必须对应至少一种可重复的验收方式。
- 命令的权威声明位于根目录 project.manifest.json。
- 未执行、失败和不适用必须明确区分。

## 验证层级

| 编号 | 层级 | 适用时机 | 命令或步骤 | 通过标准 |
| --- | --- | --- | --- | --- |
| VERIFY-FAST | 快速检查 | 每次相关修改后 | dotnet build .\b-Code\HistoryJuno\HistoryJuno.csproj -c Release | 0 警告、0 错误 |
| VERIFY-UNIT | 自动验证 | 账号或页面协议修改后 | dotnet run --project .\b-Code\HistoryJuno.Tests\HistoryJuno.Tests.csproj -c Release | 全部 PASS，0 警告、0 错误 |
| VERIFY-FULL | 完整回归 | 合并或里程碑收口前 | powershell -File .\b-Code\Test-ProjectContract.ps1 -Instantiation | 项目合同和占位符检查通过 |
| VERIFY-ACCEPT | 交付验收 | 宿主提交后 | 打开 sub2api 页面，切换账号状态/服务状态并执行刷新 | 默认账号页只列 OpenAI OAuth 且显示 5h/7d；服务页四行；停止动作出现确认 |

## 环境前提

- 操作系统或设备：Windows 10/11。
- 工具与版本：.NET SDK 9、目标框架 net8.0、HistoryVulcan 5.1.2、HistoryAurora 1.9.2。
- 外部服务或材料：本机 Sub2API 脚本目录；账号实值验收需 Sub2API 已由用户启动；端口未监听时
  服务状态应显示“未连接”，账号读取返回脱敏的启动提示。

## 证据保存

| 证据类型 | 保存位置 | 是否入库 | 保留规则 |
| --- | --- | --- | --- |
| 构建日志 | 本次命令输出 | 否 | 保留最近一次结果 |
| 宿主验收记录 | b-Office/current/项目概览.md | 是 | 每次模块版本更新时更新 |
