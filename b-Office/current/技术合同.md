# HistoryJuno 技术合同

## 现行需求

### REQ-001 Sub2API 轻量控制面板

- 目的：在 Aurora 主页面提供比 Sub2API 网页更轻的本机控制入口。
- 要求：注册 sub2api 页面，提供启动 Sub2API、连接代理、关闭 Sub2API、刷新状态四个按钮。
- 要求：启动动作同时只允许一个任务；Ubuntu Docker 和 compose 两个阶段均有执行上限；只有 8080/9090
  实际监听才返回启动成功。
- 验收：Aurora 能解析 juno.ui.describe 和 juno.ui.actions；点击动作经总线执行对应脚本；
  启动不无限等待且重复点击返回明确提示；状态表显示四个端点。
- 关联组件：b-Code/HistoryJuno/JunoPages.cs、JunoCommandCatalog.cs。
- 关联验证：VERIFY-FAST、VERIFY-ACCEPT。

### REQ-002 Juno 三子页面

- 目的：在控制面板直接管理 OpenAI OAuth 账号状态与 5h/7d 已用额度，同时保留服务端口诊断。
- 要求：控制按钮下方使用 juno.section 选择器切换“账号管理”、“服务状态”和“账号导入”；默认账号管理。
- 要求：账号查询登录本机 Sub2API 管理端，分页读取并在客户端二次过滤 OpenAI OAuth 账号，
  再批量读取 current usage；凭据、令牌、原始响应和账号凭据不得出现在输出中。
- 要求：状态覆盖限流、过载、错误、临时不可调度、停用、暂停调度与正常；额度使用
  “已用 N% · 剩余时间后重置”格式，无窗口显示“-”，单账号失败显示“获取失败”。
- 验收：页面描述只注册 sub2api 一个顶层页面，包含三个 case 的 switch；账号行只含 account、group、status、proxy、fiveHour、sevenDay 字符串字段；
  view=status 和无 view 的兼容行为不变。
- 关联组件：b-Code/HistoryJuno/JunoPages.cs、Sub2ApiAdminClient.cs。
- 关联验证：VERIFY-UNIT、VERIFY-ACCEPT。

### REQ-003 账号管理检索

- 目的：在账号较多时按业务分组和调度状态快速收敛账号列表。
- 要求：主页面标题为 `Juno`，默认子页名为“账号管理”；账号表上方提供“检索分组”和“检索状态”
  两个 Aurora 多态选择框。分组候选通过 `optionsSource` 动态读取，任一选择变化后自动重取账号表。
- 要求：账号表增加分组和代理列；筛选只影响页面投影，不改变 Sub2API 账号状态。
- 验收：页面描述包含两个选择通道；取数参数引用通道值；分组/状态组合筛选自动验证通过。
- 关联组件：b-Code/HistoryJuno/JunoPages.cs、Sub2ApiAdminClient.cs。
- 关联验证：VERIFY-UNIT、VERIFY-ACCEPT。

### REQ-004 账号导入与全局代理

- 目的：在 Aurora 内完成 Sub2API 账号导入，不再依赖独立 9090 网页作为主要入口。
- 要求：在 Juno 内提供“账号导入”子页，与账号管理、服务状态同级，使用 Aurora `sourcePicker` 作为“JSON 来源”，动态选择导入分组；
  导入按钮使用 Ask 确认，且同一时刻只允许一个导入任务。
- 要求：导入前读取活动代理并按 `ip_address` 去重；必须恰好只有一个有效代理 IP，0 个或多个不同 IP
  均拒绝导入。导入成功后识别新增账号，逐个绑定所选分组和该全局代理。
- 要求：三个子页共用顶部服务控制面板提供启动 Sub2API、代理重连、关闭和刷新；JSON 内容、账号凭据、管理密码、令牌、
  原始响应与响应错误体不得进入日志、确认文本、命令结果或页面数据。
- 验收：页面协议含来源选择器、动态分组及共享服务控制动作；模拟 API 验证导入、识别新增账号、读取详情、
  写回 group_ids/proxy_id 的完整顺序；多个代理 IP 被门禁拒绝。
- 关联组件：b-Code/HistoryJuno/JunoCommandCatalog.cs、JunoPages.cs、JsonSourcePicker.cs、Sub2ApiAdminClient.cs。
- 关联验证：VERIFY-UNIT、VERIFY-ACCEPT。

## 系统架构

### 系统边界

模块负责命令注册、WSL/Docker 启动、PowerShell 脚本调用、TCP 端口探测，以及 Sub2API 账号查询/导入/配置；Aurora 负责
页面渲染、选择通道、switch 和按钮交互；Sub2API 与代理进程由现有脚本及其外部部署负责。

### 组成

| 组件 | 路径或位置 | 职责 | 输入 | 输出 |
| --- | --- | --- | --- | --- |
| 命令目录 | b-Code/HistoryJuno/JunoCommandCatalog.cs | 注册 UI 协议和业务动作 | CommandBus | CommandResult |
| 页面描述 | b-Code/HistoryJuno/JunoPages.cs | 生成页面、动作和状态 JSON | Aurora 拉取请求 | JSON 字符串 |
| 管理客户端 | b-Code/HistoryJuno/Sub2ApiAdminClient.cs | 登录、分页查询、导入与分组/代理配置 | 本机凭据、HTTP | 脱敏账号快照或导入摘要 |
| 来源选择器 | b-Code/HistoryJuno/JsonSourcePicker.cs | 通过系统文件对话框选择本机 JSON | 用户选择 | JSON 绝对路径 |
| 启动运行器 | b-Code/HistoryJuno/Sub2ApiStartupRunner.cs | 分阶段启动 Ubuntu Docker 与 compose | 部署目录、超时策略 | 阶段结果 |
| 脚本运行器 | b-Code/HistoryJuno/Sub2ApiProcessRunner.cs | 调用停止和代理连接 PowerShell 工具并约束整体时长 | 脚本名、参数、超时策略 | 退出码和脱敏输出 |
| 外部工具 | %USERPROFILE%\Desktop\easyTOOL\SU2API | 停止 Sub2API、重连代理 | PowerShell 参数 | 服务或代理状态 |

### 关键流程

1. HistoryVulcan 装载模块，HistoryJuno 注册 juno 域命令。
2. Aurora 拉取 juno.ui.describe 和 juno.ui.actions，建立 sub2api 页面。
3. 页面默认调用 juno.ui.data view=accounts，经登录、分页过滤和批量额度查询生成账号行；分组/状态通道变化时重取。
4. juno.section 在账号管理、view=status 服务状态和账号导入间切换；启动动作依次执行
   `sudo -n service docker start` 与 `docker compose up -d`，并在返回成功前校验 8080/9090；
   停止和代理动作继续执行原脚本。
5. 刷新动作调用 aurora.ui.refreshdata page=sub2api，重新读取 Juno 子页的数据。
6. 账号导入页从 sourcePicker 取得 JSON 路径、从动态候选取得分组；导入前确认全局代理唯一，
   POST 导入后以账号 ID 差集识别新账号，再写回分组和代理，最后由刷新动作重取列表。

### 不变量与生成物边界

- 不变量：按钮只绑定动作 ID；ui.describe、ui.actions、ui.data 均为只读内部协议。
- 不变量：账号页面只投影展示字段，不返回登录令牌、凭据、原始响应或错误响应体。
- 不变量：导入 JSON 和账号详情中的 credentials 只在当前调用内存中存在，任何失败回执都只返回固定脱敏文本。
- 权威源：b-Code/HistoryJuno。
- 可重建生成物：C:\Users\Administrator\Desktop\easyTOOL\SU2API\.build。
- 正式发布物或消费快照：由 HistoryVulcan 模块提交管线生成，当前不直接写入宿主运行区。
