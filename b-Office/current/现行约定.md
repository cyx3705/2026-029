## 取舍

- **启动不走工具脚本。** `sub2api-tool.ps1` 在 Docker 起来之前先探外网代理，代理异常时桌面按钮永远等不到回执。启动只跑 `sudo -n service docker start`（30 秒封顶）和部署目录里的 `docker compose up -d`（90 秒封顶），8080 与 9090 都在听才算成功。停止和代理重连仍调用脚本。启动不顺带改代理；要修代理得另点「连接代理」。
- **额度不在这里重算。** 登录本机管理接口，分页滤出 OpenAI OAuth 账号，再用 batch usage 读被动快照。服务没起来或读不到凭据时，账号页给出脱敏提示，服务状态页仍可单独看。
- **导入只接受恰好一个出口 IP。** 活动代理按 `ip_address` 去重；一个 IP 时取该组里最小的代理 ID，导入后把新增账号绑上所选分组和这个代理。零个或多个不同 IP 时，在产生导入副作用之前拒绝。代理 IP 还没探测到，先点「代理重连」。
- **不引用 Aurora 程序集，也不自建窗口。** 页面只交 JSON。来源选择用 Aurora 的 `sourcePicker`，动态分组用 `optionsSource`（Aurora ≥ 1.9.2）；文件对话框由隔离的 PowerShell STA 进程打开，取消不改现有输入。场景隔离要 Aurora ≥ 1.21.1。

## 真机才知道的

- **F 盘工作树的默认 `obj` 建不出来。** `commands.build` 因此把中间文件和输出指到本机 Sub2API 工具目录下的 `.build`。工作区能编过，靠根上的 `Directory.Build.props` 接上 `vulcan.dev.start` 写入的宿主快照。
- 工具脚本根优先 `SUB2API_TOOL_ROOT`，否则桌面 `easyTOOL/SU2API`。部署目录优先 `SUB2API_DEPLOY_ROOT`，否则 `%USERPROFILE%/Projects/sub2api-deploy`，只在内存里读 `CREDENTIALS.txt` 的 `ADMIN_EMAIL` 与 `ADMIN_PASSWORD`。管理接口固定 `http://127.0.0.1:8080`。
- 导入 JSON 最大 16 MB、只收 `.json`、整次导入 120 秒封顶。根对象可以是 Sub2API 的 `data.accounts`，也可以直接带 `accounts` / `proxies`；缺的 `data` 包装和 `exported_at` 由模块补上。

## 工程约定

- 发版改三处版本号：`HistoryJunoVersion.props`、`module.manifest.json`、`project.manifest.json`。漏改 `module.manifest` 时宿主静默跳过整个模块。最低宿主 HistoryVulcan 6.0.0。
- 页面声明 `scene=HistoryJuno`。用户保存的各场景布局优先；刷新不得打开别的场景的页面。
- 凭据、令牌、账号 JSON、原始响应和错误体不进日志、确认文本、命令结果或页面数据。失败回执用固定脱敏文本。
- 不常驻后台线程，只在点击或刷新时探测。探测的端口是 8080、9090、7890、17890。
- 项目合同检查自带规则（共享的 `OneHistory.ModuleContract.ps1` 不在库中）。
- `z-Publish/** binary` 让快照按原始字节入库，否则主树快照和自己的 `SHA256SUMS` 对不上，finish 热装失败。
