# HistoryJuno 有效决策

这里只保留当前仍有效、会影响后续实施的决策。

## DEC-001 使用 Aurora 描述化页面

- 状态：已接受
- 日期：2026-08-31
- 背景：Aurora 已提供页面注册协议，独立网页会增加资源和维护成本。
- 决策：模块只返回 ui.describe、ui.actions、ui.data JSON，不创建 WPF 窗口。
- 原因：页面直接进入 Aurora 中央主区域，并保持与宿主主题、确认和命令总线一致。
- 后果：按钮动作必须先在 juno.ui.actions 声明；页面布局由 Aurora 负责。
- 替代或废止条件：Aurora 页面协议 V1 被正式废止时迁移到宿主公布的新协议。

## DEC-002 启动直连 WSL/Docker，停止与代理复用工具脚本

- 状态：已接受
- 日期：2026-08-31
- 背景：本机已有 sub2api-tool.ps1 和 proxy-reconnect.ps1。
- 决策：启动动作直接分阶段执行 Ubuntu `service docker start` 和部署目录中的
  `docker compose up -d`；停止和代理连接继续通过脚本运行器调用。启动限制并发和各阶段时长，
  完成后以 8080/9090 端口作为成功判据。
- 原因：原启动脚本在 Docker 启动前执行外网代理探测，代理异常时会永久阻塞，无法满足桌面按钮的确定回执；
  两条必要 Docker 命令已在本机独立验证可重复执行。
- 后果：启动不再自动同步代理配置；需要代理修复时显式点击“连接代理”。部署目录不可用、
  WSL/Docker 超时、重复启动或端口未就绪时，控制面板返回明确失败信息。
- 替代或废止条件：工具脚本接口发生不兼容变更时重新适配。

## DEC-003 账号额度使用本机管理接口只读投影

- 状态：已接受
- 日期：2026-08-31
- 背景：服务端口状态不足以判断 OpenAI OAuth 账号是否可调度及 5h/7d 额度。
- 决策：模块从本机 Sub2API 管理接口登录、分页读取 OpenAI OAuth 账号，并使用 batch usage
  接口读取被动额度快照；页面只投影账号名、状态和两个额度字符串。
- 原因：复用 Sub2API 权威状态和批量接口，不在 Juno 重算额度，也不主动探测上游账号。
- 后果：账号实值依赖 Sub2API 已启动及 CREDENTIALS.txt 可用；失败信息必须脱敏，服务状态页仍可独立使用。
- 替代或废止条件：Sub2API 管理接口或认证合同发生不兼容变更时重新适配。

## DEC-004 复用 Aurora 通用来源与动态选项组件

- 状态：已接受
- 日期：2026-08-31
- 背景：账号导入需要 JSON 文件来源，账号管理和导入都需要可检索的动态分组选择。
- 决策：复用 Aurora 1.9.2 的 `sourcePicker` 和 `textbox mode=select + optionsSource`；Juno 只提供
  选择命令、候选取数和业务动作，不复制 Minerva 控件、不引用 Aurora 程序集、不自建 WPF 页面。
- 原因：组件行为和主题由 Aurora 单一维护，Juno 只保留 Sub2API 语义。
- 后果：部署环境必须带支持 sourcePicker/optionsSource 的 Aurora 1.9.2；来源文件对话框由 Juno 的
  隔离 PowerShell STA 进程打开，取消选择不改变现有输入。
- 替代或废止条件：Aurora 发布新的来源组件协议时迁移。

## DEC-005 导入账号统一绑定唯一全局代理

- 状态：已接受
- 日期：2026-08-31
- 背景：现有 Sub2API 部署的账号共享一个 win-proxy；按固定代理 ID 写死会在代理重建后失效，
  同时多个不同出口 IP 时无法确定哪个是全局值。
- 决策：导入前读取活动代理并按 `ip_address` 去重；恰好一个 IP 时选取该组中最小代理 ID，
  导入后把所有新增账号绑定所选分组和这个代理。没有 IP 或出现多个不同 IP 时在产生导入副作用前拒绝。
- 原因：把“全局唯一”落实为可验证不变量，而不是依赖固定 ID 或代理名。
- 后果：代理 IP 尚未探测时必须先执行“代理重连”；以后若改为账号独立代理池，需要新决策和新选择界面。
- 替代或废止条件：Sub2API 提供权威的全局代理设置接口，或产品改为每账号独立代理。

## DEC-008 0.4.3 发布快照按原始字节入库

- 状态：已接受；日期：2026-09-28。来源：用户授权的体系架构清理（finish 时 Vulcan 热装报 SHA-256 不匹配）。
- 决策：`.gitattributes` 追加 `z-Publish/** binary`，与另外七个 History 仓一致。
- 原因：本仓此前只有 `* text=auto`，`z-Publish` 里的文本文件入库时被规范成 LF、签出时又转成 CRLF。
  编译器生成的 xml 原本是 CRLF，`module.manifest.json` 与 `SHA256SUMS` 原本是 LF，结果主树上的快照总有文件与
  自己的 `SHA256SUMS` 对不上：finish 后从主树热装失败，同版本归档时比对不上而生成带时间戳的避让目录。
- 后果：随本版把 HistoryJuno 上一个当前快照里被规范掉的文件按其 `SHA256SUMS` 还原为原始字节后再归档。
  `history/` 里更早的归档不手改；其中能按 CRLF / LF 还原的与不能还原的，见本次提交说明与体检记录。无代码与行为变化。
